## 〇、关于「自动拍照」的现状说明

本次尝试由助手直接驱动摄像头拍摄，结果是 **未成功**，原因如下（已实测确认）：

| 检查项 | 结果 |
|---|---|
| 系统是否存在摄像头 | 存在：`Integrated_Webcam_FHD`（USB 内置摄像头，`lsusb` 可见） |
| 内核是否识别 | 已识别：`/sys/class/video4linux/` 下有 `video0`、`video1`（主次设备号 81:0 / 81:1） |
| 助手能否打开 `/dev/video0` | **否**。当前运行环境把 `/dev` 挂载成了一个只含 `null/zero/tty/...` 的隔离目录，没有 `video*` 节点 |
| 能否手动创建设备节点 | **否**。`mknod` 返回「不允许的操作」，`mount` 返回「权限不足」，均被运行环境的策略拦截 |
| `sudo` 提权 | 不可用（sudoers 配置已损坏） |

**结论：摄像头在系统层面是好的，是助手所在的执行环境被隔离，拿不到设备节点。** 因此需要走下面任一条路径：

- **路径 A（推荐）**：你在普通终端里运行 `bash capture_photos.sh`，按提示逐张拍摄。照片自动存到 `~/麦轮小车pid/视觉测量/照片/`，拍完告诉助手一声，助手接着做去畸变、量取尺寸、写图片描述。
- **路径 B**：用手机/相机按本文档的规范拍好，把照片拷进 `~/麦轮小车pid/视觉测量/照片/`（文件名按清单里的「建议文件名」）。
- **路径 C**：如果你能让 WorkBuddy 获得摄像头设备访问权限（放开 `/dev/video*`），助手就能直接驱动拍摄。

## 一、拍摄规范

### 1.1 通用要求

| 项 | 要求 |
|---|---|
| 光照 | 均匀、无强反光与阴影；底视/内部结构处需要补光（可开手机手电筒） |
| 背景 | 干净、单一颜色（白纸/纯色桌面最佳），便于边缘识别 |
| 对焦 | 主体清晰；铭牌、丝印类照片必须能读出文字 |
| 稳定性 | 尽量固定相机（三脚架或靠墙），避免运动模糊 |
| 比例参照 | 凡是**要用来量尺寸**的照片，画面内必须放入一把钢尺，且与测量平面共面 |
| 正投影 | 俯视/正视/侧视尽量做到镜头光轴垂直/平行于车体对应平面，减少透视误差 |

### 1.2 关于畸变（去畸变方案）

手机和网络摄像头都是**广角镜头**，边缘会有桶形畸变——直接影响「从照片量尺寸」的精度。处理策略：

1. **优先用画面中心区域**测尺寸。畸变在画面中心几乎为零，把车体放在画面中央，误差可以忽略。
2. **要严格量尺寸时做标定**：拍 15 张以上的棋盘格照片（见 `P15`），助手用张正友标定法算出内参 `fx, fy, cx, cy` 与畸变系数 `k1, k2, p1, p2`，再做去畸变重映射。
3. **免标定的替代法**：俯视照片里放入钢尺，用「钢尺刻度本应是直线」这一约束，反解出径向畸变系数 `k1` 并做单张校正。精度不如标定，但足以应付轮距/轴距这类 ±1 mm 的量测。
4. 去畸变后**必须重新定标比例尺**（像素/毫米），否则尺寸会系统性偏大或偏小。

> 说明：本机磁盘已用 98%（仅剩约 1.6 GB），暂时无法安装 OpenCV。等照片就位后，助手会用轻量方案实现去畸变与量测（纯 Python 数值重映射或临时清理磁盘后安装 OpenCV）。

## 四、下一步

拍照完成后，交付链路为：

1. 照片 → 去畸变 + 比例尺标定 + 关键尺寸量取
2. 尺寸 + 参数表 → **运动学转换方程**（底盘速度 ↔ 四轮转速）与**质心位置/载荷/惯量报告**
3. → **MECE 误差因素 PDF**（为什么走不直、转不准）
4. → **PID 整定方案**（速度环逐轮整定 → 航向环 → 直线/旋转验证）
