## 2. 逐条分析

### E1 · 运动学模型错误（X/O 布局、l_x/l_y、轮序映射）

- **现象**：指令「前进」车后退/斜走；原地旋转方向与期望相反；位移比例系统性错。
- **机理**：麦轮 X/O 布局决定方程形式本身；辊子手性、轮序映射、`invert`/forward 符号任一错位 → 整套方程符号失效。`l_x + l_y` 的**几何语义**若理解错，旋转力臂整体偏差。
- **当前证据**：
  - 固件轮序 `0=FL 1=FR 2=RL 3=RR`、`invert={true,false,true,false}` 与历史实验数据一致（exp1 计数 FL=−57 / FR=+53 / RL=−73 / RR=+49）。
  - 2026-10-14 实测：轴距 **140 mm**、轮距 **117 mm** ⇒ `(140+117)/2 = 128.5`，与固件 `LXY = 0.12825 m` 差 0.25 mm —— 反证 `LXY` 是 **(轴距+轮距)/2**，不是轴距（R47；**误当轴距用会差 ≈8%**）。
  - 布局 X/O 的最终照片核对仍列在 `HANDOFF.md` §6 待用户确认（当前实现按 X 型）。
- **本期是否处理**：部分 —— LXY 语义已澄清并写进 `小车档案.md` §8；`LXY` 传值 `(轴距+轮距)/2 / R` 在 Task 9 里程计里已按实测值使用。
- **责任人 / 后续动作**：用户（俯视照片确认 X/O）；若判 O 型 → 重推方程（固件线）。责任人：用户 + 固件线。

### E2 · wheel_map 过期（查表插值失真）

- **现象**：同一 duty 下实际轮速与查表预期差 40–70%（高区）；低速指令被地板钳掉、跑不到指令值。
- **机理**：`wheel_map.h` 是 duty↔ω 查表插值；表的**采集条件**（电池电压/负载）与**使用条件**不一致时，出现系统性偏差。表是一次性采集的，电池状态变化后不自动失效。
- **当前证据**：
  - 旧表高区**高估 ~40–70%**（R59：指令 30.6 rad/s → 旧表给 duty 147–168，实测该 duty 区只有 ~18）。
  - 新采**架空表**离散度 **27.4%**（>旧记录 13.5%，是真实电机个体差异 ⇒ 必须逐轮建表）；**落地表** 8 档全部采到（duty 110–240），四轮平均离散度 **10.8%**。
  - 落地表已替换进固件（2026-10-15，commit `346d896`）→ `pwm` 逐轮不同，确认生效。
  - **Step 5 速度跟踪验收未通过、未定案**：唯一带"车真在转"门禁的有效点 `RUN 0 0 -6.0 1600` → 实测偏航率 **4.39 rad/s vs 请求 6.00（−26.8%）**，判据 ±15%；且当时**电量未确认**、R62 吃掉 2/3 次测试。
  - 电压依赖已见：同 duty=110 两次采集 11.5 vs 12.9 rad/s（**差 12%**）。
- **本期是否处理**：处理中 —— 表已重采 + 替换；**下一步 = 充满电 + 断电重启后复测**（验收脚本 `实验/wheelmap_accept/verify_step5_final.py`，以 IMU 偏航率为判据）。
- **责任人 / 后续动作**：用户（充电 + 断电重启）→ 固件线（复测）；若复现，先查"测量条件 ≠ 控制条件"（`M` 直驱 vs `RUN` 协同旋转的负载/打滑不同），再决定是否重采。
- **待填（TODO(T12)）已填**（RUN 段实际轮速 —— 结论是「本批测不到稳态」）：
  - **RUN 段非零 duty 无一例外等于 ±110**（MIN_DUTY 地板）：直行/横移/原地旋转的 RUN 段 **4848/4848** 个采样 `|pwm|=110`，**无逐轮差异** → 新表在本批控制条件下**未起逐轮区分作用**。
  - **斜行是例外且不算缺陷**：X 型布局的 45° 斜行只驱动一个对角对 —— 实测 `pwm_fr=+110`、`pwm_rl=−110`、`pwm_fl=pwm_rr=0`（`invert={true,false,true,false}` ⇒ 板级 −RL 即逻辑前进，两轮同向前进）；故斜行的 48 个「轮次」里 24 个**恒为 0**。
  - 由编码器折算的轮速（`Δenc/C_1rev·2π/Δt`，C_1rev=1276/1270/1276/1274）**随取窗而变**（RUN 段仅 0.12–0.39 s，无一条进入稳态）：

    | 取窗 | n（轮次） | min | p25 | 中位 | p75 | max | 直行中位 | 旋转中位 | 横移中位 |
    |---|---|---|---|---|---|---|---|---|---|
    | 整段 RUN 首末差 | 200 | 1.07 | 4.75 | **5.98** | 7.01 | 8.31 | 7.17 | 5.58 | 3.42 |
    | 末 40% | 200 | 2.22 | 5.93 | **7.77** | 9.29 | 11.08 | 9.97 | 7.16 | 4.68 |
    | 跳过前 0.15 s | 140 | 2.95 | 7.29 | **8.64** | 9.27 | 10.06 | — | — | — |

    （单位 rad/s；三种取窗是同一批 trial，仅窗口不同。）
  - 含义：① 本批 RUN 的控制器输出**全被地板钳到 110**，剩余速度偏差由**电机个体差 + 死区（E3）**主导，而非查表分辨率；② 中位随取窗在 **6.0–8.6 rad/s** 间变化（≈1.4×）⇒ **窗口选择主导结果**，任何单点的「实测/查表 −50%」都不足以给 E2 定案。
  - **本批数据无法给出「指令轮速」与稳态占比**：RUN 只下发车体速度，逐轮目标轮速未落盘；且 RUN 时长 0.12–0.39 s 与起转死区 0.105–0.14 s（E3）同量级 ⇒ 要测稳态需 **≥2 s 恒 duty** 复测（即 Step 5 复测，需满电）。

> 口径：筛 `trial_ok=TRUE` 全部 62 条；用 `xlsx_row` 回查 `pwm_fl/fr/rl/rr`、`encoder_fl/fr/rl/rr`、`timestamp`；RUN 段 = **末段四轮 `pwm` 全非零**的连续块（斜行只驱动一对角轮，被该判据排除，故 n=200 而非 248）；轮速 = 每轮 `Δencoder/C_1rev×2π/Δt`；三种取窗并列给出（`末 40%` = RUN 段后 40% 时长；`跳过前 0.15 s` = 去掉 ≥0.15 s 起转段后取首末差）。复核脚本 `实验/t12_stats/verify3.py`。

### E3 · 死区 / 起转非线性

- **现象**：低速给不足不走、稍高就窜；正反向不对称；**小位移指令做不出来**（原地旋转一侧不动尤其明显）。
- **机理**：减速箱 + 驱动正反向非对称死区；固件 `MIN_DUTY=110` **钳位**使 duty<110 的精细补偿失效；`KICK_DUTY=105 < MIN_DUTY` ⇒ kick 是空操作，soft-ramp 未实现。
- **当前证据**：
  - 死区实测 **DZ_POS 40/48/56/44、DZ_NEG 52/48/68/60**（占空比 %）。
  - `RUN 0 0 om` 低速请求（7.7 / 15.3 rad/s）被钳到 **pwm=110（地板）**，实测 ~13 rad/s（R59）。
  - Task 10 报告：0.4 m/s 地板下 400 ms 脉冲的**最小步长 ≈160 mm**，而 `drive_to` 容差 **12 mm** ⇒ 闭环归位在真机上很可能先失败。
- **本期是否处理**：**未修** —— `MIN_DUTY` 的改动需用户裁决（台账明确"先跟用户确认再改"）。
- **责任人 / 后续动作**：用户（裁决：降 `MIN_DUTY` / 改更短脉冲 / 接受）；固件线（改）。
- **实测幅度**：死区 40–68%；地板速度 ≈0.4 m/s；最小步长 ≈160 mm（vs 归位容差 12 mm）。

### E4 · brownout 掉电复位（并含两类通信缺陷）

- **现象**：四电机同转时 ESP32 复位、指令丢失、数据截断；RUN 中途遥测**静默**（PC 分不清"跑完"还是"板子死了"）。
- **机理**（三类，已分离）：
  1. **电学**：4 电机同时驱动 → 涌入电流拉低电源 → brownout 复位（USB 供电更易触发）；
  2. **写阻塞**：`WiFiClient::write` 在 socket 不可写时阻塞，把 `loop()` 冻在写调用里 → 100 Hz 采样停摆（commit `e2600b7` 修：`send(MSG_DONTWAIT)` 非阻塞 + 环内补发）；
  3. **僵尸客户端**：socket "TCP 层连着、`send()` 已不成功"时 `client.connected()` 仍为真 → 永不 accept 新连接、环被填满（含 `DONE`）→ "跑一段就彻底静默、跨新连接不复原、断电才恢复"（R62；commit `9045e70` 修：接受前 `client.stop()` + TX 停摆看门狗 + 失联停车）。
- **当前证据**：
  - 2026-10-13 **USB 供电**四轮同驱复位 1 次；**电池供电下缓解前后均未复现**（0/5、24/24 无缺口）→ 无法归因"缓解有效"。
  - 写阻塞修复前后：**34/69（49%）** 的 RUN 有 >150 ms 遥测缺口 → 修后 **24/24 无缺口**。
  - R62 修复后重连压测 **34/36**（修复前 36 轮 5 轮失败）；确定性背压 3/3 触发 → 修复后新连接在旧连接开着时被正常服务；看门狗机上验证停车生效（标称 12 s 的 RUN 在 t+3.98 s 停转）。
  - ⚠ 环境注记：R62 会话后段板子**反复整体掉电重启**（复位原因 POWERON、无 RESET 行），疑电池/供电不足 —— 满电后建议复跑 `实验/tcp_reconnect_stress.py` 确认 36/36。
- **本期是否处理**：**已处理**（stagger 默认 true + 三处固件修复），但 **`9045e70` 的满电复测未完**；A4 取消 ⇒ 硬件病因**无基线**。
- **责任人 / 后续动作**：用户（充电/断电重启/插拔接插件检查）→ 固件线（复跑压测与验收）。
- **实测幅度**：见上（1 次 USB 供电复位；0/5 与 24/24；34/36 压测）。**brownout 在满电电池下的发生率：无数据（TODO）**。

- **机理**：陀螺零偏 + 标度误差（k_yaw、b_z 未标）；安装符号若与车体不一致，航向环方向就反。
- **当前证据**：
  - 静置 yaw 漂移 **−0.06°/min**（架空诊断）。
  - 符号一致性：R63 那次落地测试里 IMU 偏航率 1.64 rad/s 与轮速推算 1.83 rad/s **同号且量级一致（90%）**。
  - 标定量 `k_yaw` / `b_z` 仍未测（参数表待填）。
- **本期是否处理**：部分 —— Task 11 内置 `yaw_sign_ok` 判据把"符号反"大声暴露（`yaw_diff_deg ≈ ±90°` 形态）；标定未做。
- **责任人 / 后续动作**：后续标定任务（回填 k_yaw/b_z）；实验线可从 Task 12 数据顺手看漂移率。
- **待填（TODO(T12)）已填**（直行漂移率 + IMU 对比，21 条）：
  - 视觉航向漂移率（**有符号**）：中位 **−1.3 °/m**（min −22.08 / p25 −8.97 / p75 +9.61 / max +15.52）；**取绝对值**中位 **9.04 °/m**（min 1.27 / p25 5.31 / p75 12.41 / max 22.08）；腿长仅 0.15–0.20 m，°/m 对端点测量极敏感（n=21）。
    ⚠ **Task 14 复算更正**：符号中位近 0 **不是「左右偏各半」**，而是**前进（恒负）与后退（恒正）被平均掉** —— 分开看两组各自 100% 同号（见 E8 末条）。
  - IMU 航向漂移率（`imu_yaw` RUN 段首末 / 腿长）：**有符号**中位 **−0.44 °/m**（min −14.67 / p25 −5.63 / p75 +5.30 / max +8.55）；**取绝对值**中位 **5.63 °/m**（n=21，同一批 trial）。
  - 直行 `imu−vision` 符号差：中位 −0.38°（min −1.44 / max +2.23，n=21）⇒ 6 Hz IMU 与视觉在直行段**同量级、无符号反转**；E14/E15 在实跑里的代价体现为**采样稀疏（±1° 级）而非常数偏置**。
  - 视觉 |漂移率|（9.0 °/m）略高于 IMU（5.6 °/m）但与之同号同量级、互不矛盾 ⇒ 漂移是**机械的**、不是视觉链路的伪影；但**归因（轮间不等 vs 打滑）本批不足以分离** —— E8 的左右计数差与漂移率相关仅 `r=−0.32`（n=21）。

> 口径：筛 `trial_ok=TRUE` 且 `action=straight` 21 条；IMU 用 `xlsx_row` 回查 `imu_yaw` 在 **RUN 段首末**两点之差（回绕折算到 ±180°），视觉取汇总行 `vision_yaw_deg`/`vision_dist_mm`；腿长 <10 mm 的行剔除；有符号与绝对值两组分位并列给出；n=21。复核脚本 `实验/t12_stats/verify2.py`。

### E16 · 视觉测量误差（真值链自己的误差）

- **现象**：真值本身带噪声与系统差；"用尺子去量尺子"。
- **机理**：
  1. PnP 角点亚像素噪声（帧/光/运动模糊）；
  2. **畸变模型选择**：棋盘始终位于画面中部 → 高阶畸变/主点不可辨识 → 取针孔（`dist=0`）；
  3. 相机自动对焦的帧间抖动（不锁焦，R49/R53）；
  4. 场地四码**不是完美矩形**（贴装 + 透视残差）。
- **当前证据**：
  - 重投影 RMS：参考照片五码 **0.068–0.846 px**（ID20 最差 0.846）；A1 五码齐帧 **0.11 px**；复测 160 帧均值 **0.13** / 最大 **0.34 px**。
  - 帧间重复性（同位置 20 帧）：x 极差 **1.22 mm** / y **0.76 mm**（σ≈0.3 mm）——单帧打不满 1 mm。
  - A2 单点残差：x 2.1 / y 7.1 mm、dyaw 1.08°（y 的 7.1 mm 尚未归因：疑人那条"顶边"参照，且位移差分时消掉）。
  - 四码底边 y 差 **8.2 mm**、右侧 x 差 0.2 mm；ID22 离拟合平面 15.2 mm（Task 10 警告）。
  - 内参系统不确定度：fx 范围 1417–1516 px（引用时给范围）。
- **本期是否处理**：处理中 —— PnP 主路径 + 桌面单应降级为交叉校验；不锁焦/不写 FOCUS 已有实测结论。
- **责任人 / 后续动作**：实验线（Task 12 逐条对比三条独立链路）；若 y 有**随位置变化**的系统误差 → 回头查内参/边界码贴装/重拍棋盘铺到画面四角；若为**常数偏置** → 位移差分豁免（R55 的结论）。必要时按位置多帧取中位（R49），**不是**去调 FOCUS。
- **待填（TODO(T12)）已填**：
  - 视觉 vs 里程计逐条残差（平移 47 条）`odo−vision`：min +0.46 / p25 +2.53 / 中位 +3.55 / p75 +8.37 / max +11.98 mm —— **系统性 +5% 偏置**（与 E6 同源），非随机噪声。
  - **PnP vs 桌面单应并排交叉校验：本批数据无法给出**——汇总行只落 PnP 结果，未同时落 `H_px2mm` 输出。仍只有一个**物理推算**（保留标注）：ID29 高出桌面 ≈78 mm ⇒ 桌面单应将位置沿视线径向放大 ≈ 517.5/438.4 ≈ **+18%**（非实测）。

> 口径：筛 `trial_ok=TRUE` 62 条；残差用 `odo_dist_mm`/`vision_dist_mm`（平移 47）算 `odo−vision` 分位；PnP-vs-单应差需同一批照片同时跑两路解算（本批未落盘）；n=47。
