## 1. Intent 与 Why

**目标**：小车在**四个固定边界 ArUco 码围成的区域**内运动，用**车载 ArUco 码 + 摄像头**作为 ground truth，自动记录**平面轨迹（位移 mm）与旋转角度（deg）**，取代 22 条实验里"人手 + 尺子"的人工测量。

**Why now**：人工测量既慢又不可靠；相机已标定内参；架空诊断暴露了三个硬伤（wheel_map 过期 ~50%、brownout 掉电、IMU 仅 6 Hz），不先修则视觉真值与内部传感器对不齐。

**成功定义**：一条指令（走/转）跑完，**零用户手工介入**，PC 自动产出该次运动的视觉真值（起/中/终：位移 mm + 转角 deg），并与编码器/IMU 解算并列对比入表。

**反目标**：出现"每条实验还要人工介入"= 失败。

## 2. 小车信息（已验证的物理事实）

### 2.1 硬件

| 项目 | 值 |
|------|-----|
| 主控 | ESP32-D0WD-V3 |
| 电机 | 4 × `TK-ENC-TT-26B V1.2`，编码器仅 A 相 |
| IMU | `GY-25T`，Serial2 RX=**GPIO38**（37 无数据），9600 8N1 |
| Wi-Fi | `B1222`，TCP 8266 / UDP 8267 / OTA `mecanum` |
| 供电 | 电池 + USB（CH340 兼串口） |

### 2.2 引脚（代码已核对：`main.cpp:48,71`）

电机 `FL{13,15} FR{12,14} RL{27,26} RR{25,33}` · 编码器 `FL32 FR34 RL35 RR36`

### 2.3 轮子编号（固件索引 0–3）

| 索引 | 名称 | 位置 | 电机 | 编码器 | forward 符号 |
|---|---|---|---|---|---|
| 0 | **FL** | 左前 | 13,15 | 32 | −1 |
| 1 | **FR** | 右前 | 12,14 | 34 | +1 |
| 2 | **RL** | 左后 | 27,26 | 35 | −1 |
| 3 | **RR** | 右后 | 25,33 | 36 | +1 |

`invert[4]={true,false,true,false}`（`wheel_map.h:104`）与历史数据（exp1: FL=−57,FR=+53,RL=−73,RR=+49）一致。
车体系：X 前、Y 左、ω 逆时针为正，原点 = 四轮轴心俯视投影矩形中心。

### 2.4 **车载 ArUco 码位置**（关键）

- 车载码 = **ID29**，黑色有效区边长 **30 mm**（实测确认），约 100 px
- 位置：**左甲板**（带绿/黄/红/蓝按钮那侧），即**左前轮 FL 与左后轮 RL 之间的上方**
- 参考：`photo_review_20261013.jpg` 中中心 (837, 324) px

> **推论**：码偏置在**左侧**，不在几何中心。视觉位移/转角必须以**码实际位姿**为准，偏置 `(dx,dy,dθ)` 需标定（§6.4）。

### 2.5 场地边界码（固定）

| ID | 角 | 黑色有效区边长 |
|----|----|--------------|
| 20 | TL | **25 mm** |
| 21 | TR | **25 mm** |
| 22 | BR | **25 mm** |
| 23 | BL | **25 mm** |

### 2.6 场地几何（实测码尺寸推算）

- 场地 ≈ **505 × 252 mm**（长×短），对角线 565 mm
- 车体包络 **270 × 149 mm** → 纵向余量 **235 mm**，横向余量 **103 mm**
- **约束**：转 90° 后车宽方向变 270 mm > 短边 252 mm → **只做小角度旋转**（≤45°）

## 3. Goals / Non-goals / Constraints

### Goals
1. **视觉真值管线**：起/中/终三点，自动产出位移 mm + 转角 deg
2. **固件加固**：wheel_map 重建（架空+落地两套）、brownout 软件缓解、遥测增强
3. **参数表更新**：依据照片 + 实测修正 `交付物/麦轮小车参数测量清单.xlsx`
4. **MECE 误差分析**：第一性原理穷尽拆分
5. **全自动实验**：PC 驱动，零手工

### Non-goals
- ❌ 完整闭环 PID 整定（本期先把测量与硬伤修好）
- ❌ 动态特性全测（τ_m、斜坡等）
- ❌ 更换硬件 / IMU 提速（**用户已决定：IMU 保持 6 Hz**）
- ❌ 大角度旋转（>45°）

### Constraints
- 4 边界码固定 → 场地系每批实验前复核一次即可
- 编码器单相 → 不能辨向
- **IMU 仅 6 Hz → 降级为"粗略交叉校验"，主真值是视觉**
- 相机与遮挡箱**已固定**（用户确认）
- 电池电压**无 ADC 采集**（`grep analogRead` 无结果）→ 电池健康靠一次性人工测量

## 4. 关键决策（全部经用户确认）

| # | 决策 |
|---|------|
| D1 | **视觉解法 = `solvePnP`**（弃用桌面单应作主路径）。码尺寸已知（25/30 mm），PnP 解三维位姿，**消除悬空 55–75 mm 造成的 10–17% 尺度偏差**。原 `usable:false` 单应降级为交叉校验 |
| D2 | **yaw 参考系 = 场地系**（图像 up = 0°），绝对航向可比 |
| D3 | **拍摄 = 起/中/终三点快照**（非全程视频） |
| D4 | **PC 驱动自动化**：PC 发指令 + 触发相机，全自动 |
| D5 | **掉电：先测电池，再写软件**（hardware-first 诊断 → 软件缓解） |
| D6 | **归位 = 视觉闭环回原点**（视觉伺服，每条实验前自动开回） |
| D7 | **接受一次性人工标定**（量 ID29 偏置 + 尺子验证视觉精度） |
| D8 | **实验矩阵按场地重设计**，小幅位移，**只做 ≤45° 旋转** |
| D9 | **先建新固件再对比**（不采旧固件基准，避免 brownout 污染） |
| D10 | **wheel_map 重建采两套**：架空套（诊断电机一致性）+ 落地套（实际控制） |

## 5. MECE 误差分析（第一性原理）

按物理因果链 MECE 拆分"走不准 / 转不准"：

### 5.1 指令 → 轮速（PWM）层
- **E1** 运动学模型错误：X/O 布局、l_x/l_y、轮序映射
- **E2** wheel_map 过期：架空实测表高估 ~50%、四轮离散 **13.5%**
- **E3** 死区/起转非线性：`MIN_DUTY=110` 绕过低速补偿、正反死区不对称（40/48/56/44 vs 52/48/68/60）
- **E4** brownout 掉电复位：4 电机同转 → ESP32 复位 → 指令丢失、数据截断
- **E5** **开环本质**：无反馈校正，误差累积（闭环解决）

### 5.2 轮速 → 车体运动（物理）层
- **E6** `R_eff` ≠ `D/2`
- **E7** `C_1rev` 标定误差（1276/1270/1276/1274）
- **E8** 轮间不等：前后轮距 120/118 不等、磨损差异
- **E9** 横移交叉耦合 ε_xy
- **E10** 侧滑/打滑（μ1/μ2）
- **E11** 地面不平/接地点差异

> ⚠️ **待复核**：`v1_values.json` 记"四轮接地点共面=**是**"，而 xlsx"一次性检查"记"**否**"。两份数据冲突，**需实测复核**（属 D7 一次性人工步骤）。

### 5.3 感知 → 真值（测量）层
- **E12** **人工测量误差**（历史 22 条实验的根源 → **本期用视觉消除**）
- **E13** 编码器单相不可辨向
- **E14** IMU 6 Hz 速率不足
- **E15** IMU 符号/零偏
- **E16** 视觉测量误差：PnP 角点噪声、畸变模型选择（棋盘只覆盖画面中部 → 高阶畸变不可辨识，取针孔）

### 5.4 措施归属
- 本期：E2（重建表）、E4（掉电缓解）、E12（视觉替代）、E16（PnP）
- D5 诊断：电池健康、接插件
- 闭环解决：E5
- 后续：E6/E7/E8/E9/E10/E13/E14/E15

## 6. 设计

### 6.1 总体架构

```
[PC 调度器]                                        [ESP32 小车]
  ├─ 归位: 视觉闭环开回原点 ──┐
  ├─ 选实验(矩阵已按场地裁剪) │
  ├─ 拍起/中/终三图 ───────────┤  Wi-Fi(8266)
  ├─ 下发 RUN vx vy om ms ───────> 固件: 运动学→wheel_map→PWM
  ├─ 收 100Hz 遥测(IMU+4编码器) <──── 回传
  └─ solvePnP → 场地系 → 真值 → 对比入表
  
  [一次性人工, D7]: 量 ID29 偏置 / 尺子验证精度 / 复核共面 / 测电池
```

### 6.2 视觉真值解算（D1 核心）

1. **场地系重建**：对 4 个边界码各跑 `solvePnP`（25 mm）→ 得到相机系下的四点 → 构造场地系（原点=形心，X=TL→TR，Y=TL→BL）→ 得 `H_cam2field`
2. **车体位姿**：对 ID29 跑 `solvePnP`（30 mm）→ 相机系位姿 → 变换到场地系 → `(x_mm, y_mm, yaw_deg)`
   - **PnP 直接解出码的高度**，悬空不再是误差源
3. **偏置修正**：ID29 在左甲板，用标定得到的 `(dx,dy,dθ)` 把"码位姿"换算成"车体原点位姿"
4. **输出**：起/中/终三点 `(x,y,yaw)`；净位移 = end−start；净转角 = yaw_end−yaw_start；中点用于检查路径形状
5. **备用/交叉校验**：原 `H_px2mm` 桌面单应，与 PnP 结果比对，偏差过大则告警

**精度估算**：ID29 ≈100 px、相机 ~0.44 m、K fx=1460.76 → 角点亚像素 ~0.3 px → 位置分辨率 ≈ **0.1 mm**。满足需求。

### 6.3 固件改动（USB 烧录，命令走 Wi-Fi）

| 改动 | 对应误差 | 要点 |
|------|---------|------|
| wheel_map 重建 | E2 | **两套表**（架空诊断用 + 落地控制用），按轮按方向 |
| brownout 缓解 | E4 | 4 电机**错开起转**（每轮错开 ~30–50 ms）+ soft-ramp；⚠️ 注意这会引入 ~150–200 ms 侧向/偏航瞬态，需在解读时考虑或改为先测电池确认硬件无碍再决定是否启用 |
| 遥测增强 | 全局 | run 期间**改为实时流式**（当前是全缓冲到 `DONE` 才发 → PC 中途收不到，无法区分"跑完"和"板子死了"）；加时间戳 |
| 掉电告警 | E4 | 用 `RTC_DATA_ATTR`/NVS 存 run-id + `ESP.getResetReason()`，**下次连接时回报**（brownout 本身无法实时上报，板子已死） |
| 保留命令 | — | `RUN/PING/ID/ZENC/STOP/DONE`；命令**只从 Wi-Fi TCP 进**（串口仅调试输出，现有架构不变） |

**注意**：现有 150 ms `KICK` 是**空操作**（`KICK_DUTY=105 < MIN_DUTY=110`，kick 永远抬不高）。soft-ramp 是**新行为**，不是缓解既有行为。

### 6.4 一次性人工标定（D7）

| 步骤 | 内容 |
|------|------|
| A1 | 量 ID29 相对"四轮轴心矩形中心"的平面偏置 `(dx,dy)` 与朝向偏置 `dθ` |
| A2 | 用尺子把车摆在 3–5 个**已知位置**，验证视觉解算精度（决定 PnP 是否可信） |

### 6.5 实验矩阵（D8 重设计，按场地裁剪）

场地 505×252、车体 270×149、纵向余量 235 / 横向余量 103 mm：

- **直行**：前进/后退，距离 ≤ **200 mm**，2–3 个速度档，每档重复 ≥3 次
- **横移**：左右，步长 ≤ **80 mm**（横向余量只有 103 mm）
- **斜行**：45° 方向，位移 ≤ **120 mm**
- **旋转**：**仅 ≤45°**，顺/逆时针；**不做 90°/180°**（车宽会超出短边）
- 每条实验：起/中/终三点视觉真值 + 遥测，并排入表
