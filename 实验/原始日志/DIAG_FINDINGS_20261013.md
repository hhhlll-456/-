# 架空诊断发现（2026-10-13）

> 场景：小车抬起、四轮悬空，USB 线连电脑（CH340 串口 + 供电），Wi-Fi TCP 命令。
> 脚本：`实验/diag_air2.py`（v1 有 STREAM 未重开的 bug，v2 修复）。
> 原始日志：`diag_air2_20261013_174648.txt` / `_report.txt`

## 1. 固件验证 ✓

- 启动日志确认烧的是 **exp 实验固件**（`=== MECANUM experiment FW ===`）
- 芯片：**ESP32-D0WD-V3**，双核，Wi-Fi 连接 B1222 正常（RSSI ≈ -55）
- TCP 命令接口正常（PING/ID/SNIFF 有回应）
- **串口是调试输出-only**：命令只能从 Wi-Fi TCP 进（`handleLine` 只挂在 TCP client 上），USB 串口只出日志

## 2. IMU（GY-25T）验证

| 指标 | 实测 | 评价 |
|------|------|------|
| 静态 yaw 漂移 | **-0.06 deg/min**（RMS 0.004） | 优秀，传感器本身稳定 |
| 静态 roll | -0.15° | 接近水平 |
| 静态 pitch | **+1.76°** | 安装倾角，软件应归零 |
| **有效更新率** | **~6 Hz** | ⚠️ 严重瓶颈 |

- **9600 波特是瓶颈**：遥测 100Hz 但 rpy 值每秒只变 ~6 次 → IMU 串口有效帧率仅 ~6Hz
- GY-25T 支持更高波特率（最高 115200），需重新配置模块 + 改固件 `Serial2.begin`
- 6Hz 的 yaw 反馈对闭环角速度控制远远不够

## 3. 编码器验证

- 静置 10s 增量 **[0,0,0,0]** — 无电气噪声假计数 ✓
- **单相（仅 A 相）**：只能计数不能辨向 — 已知限制

## 4. 电机验证（空载，PWM=120，逐轮）

| 轮 | Δenc/1.5s | 实际 rad/s | wheel_map 表值 |
|----|-----------|-----------|----------------|
| FL | 4514 | **14.96** | 24.20 |
| FR | 4966 | **16.57** | 24.78 |
| RL | 4762 | **15.91** | 23.53 |
| RR | 5107 | **17.13** | 26.23 |

- **四轮离散度 13.5%**（同占空比下 FL 最慢、RR 最快）
- **wheel_map.h 表整体高估 ~50%**（表 24-26 rad/s vs 实测 15-17）
- 表的逐轮补偿比例（max/min=1.08）**不足以补偿**实际离散（1.14）
- 单轮 PWM=120 不触发 brownout

## 5. Brownout — 严重 ⚠️

- **四轮同时驱动时 ESP32 brownout 检测器触发 → 复位**
- 串口日志：`Brownout detector was triggered` + `rst:0xc (SW_CPU_RESET)`
- 板子能干净恢复（Wi-Fi 2s 内重连），但**命令在复位瞬间丢失**
- 单次单轮 PWM=120 不复现 → 是**总电流**事件（4 电机 × 涌入电流）
- 当前 USB 供电（电脑口 ~500mA）很可能带不动 4 电机同时起转
- **如果 22 条实验期间也发生过 brownout 复位 → 实验被截断、航向停更、指令丢失**

## 6. 根因评估（"直行跑偏 / 转角不准"）

| 现象 | 根因 | 证据 |
|------|------|------|
| 直行跑偏 | 低速时 MIN_DUTY=110 地板**绕过** wheel_map 逐轮补偿 + 表本身 stale + 四轮 13.5% 离散 | 逐轮实测 |
| 转角不准 | RUN 是**开环**（定时，无 yaw 反馈校正）；IMU 仅 6Hz 无法闭环；brownout 复位截断运行 | 固件代码 + 诊断 |
| 传感器"不准" | IMU 静态精度其实很好（-0.06°/min）；编码器无假计数 — **不是传感器问题，是开环 + 映射 stale + 供电** | 诊断数据 |

## 7. 建议下一步

1. **确认供电**：现在是否只用 USB 供电（无电池）？如果是，brownout 是预期内的 — 需电池或外接电源
2. **重测 wheel_map**：在**落地加载**状态下重测 duty↔ω（表可能是在不同条件下测的）
3. **MIN_DUTY 策略**：低速段要么降低地板、要么接受开环漂移、要么上闭环
4. **IMU 提速**：配置 GY-25T 高输出率 + 固件改 115200 波特
5. **闭环化**：用 encoder+IMU 反馈做 PID（项目原始目标），开环 RUN 必然跑偏
